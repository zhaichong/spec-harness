# Java 后端规则

仅在任务触及 Java 服务、API、数据访问、消息处理或服务端运行时应用。遵循项目已有 Spring/Jakarta、分层、异常和测试约定，不机械创建 Controller、Service、Repository 等空壳层。

## 对焦与方案

- 明确调用方、鉴权主体、数据范围、读写行为和失败语义。
- 明确请求 DTO、响应 DTO、校验、错误码及兼容要求。
- 识别事务边界、幂等要求、并发冲突和重复请求。
- 数据变更检查表结构、索引、分页、数据量、锁及回滚。
- 外部调用明确超时、重试、部分失败和补偿边界。

## 实施检查

- 在 Controller 或消息入口等信任边界进行输入校验。
- 在业务或数据边界执行鉴权和数据权限判断，不能只依赖前端隐藏入口。
- 事务只覆盖必须保持一致的操作，避免在长事务内执行慢外部调用。
- 写操作根据业务风险处理幂等、唯一约束或并发冲突。
- 异常映射保持稳定，不向调用方泄露堆栈、SQL 或敏感数据。
- 日志记录必要上下文，同时脱敏凭据、身份信息和业务敏感字段。
- 数据迁移沿用项目现有 Flyway、Liquibase 或迁移机制，不临时自造流程。

## 最小验证

- 运行最小相关单元或集成测试，再按影响范围扩大。
- API 至少验证合法请求、一个输入边界和权限或失败路径。
- 数据写入验证事务结果、重复执行和回滚或恢复方式。
- 公共接口验证旧调用方兼容性。
- 按需运行相关模块的编译和测试；依赖、资源、生成代码或打包链变化时补充对应构建，项目规定的检查必须完成。`package` 与 `install`、`deploy` 分别判断副作用，不为验证默认执行发布或远端写入。

简短 Spec 用自然语言记录验收即可；完整追踪统一用 `AC-01` 等数字编号，领域写在描述中。

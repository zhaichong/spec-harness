# 简短 Spec 与针对性复查

只在需要留存设计或风险判断时读取。已有 issue、设计说明或用户规格足够时直接补充，不另建同内容文件；否则在 `.spec/<日期>-<简述>/spec.md` 留一份记录。默认不提交流程文件、不修改 ignore、不切分支。

## 一份记录即可

内容按任务裁剪，用自然语言写清：目标与范围、关键设计与兼容性、可观察的验收结果、实际验证结果及未决事项。不强制编号、版本字段、风险表或固定章节。不适用的部分省略，不复制代码和命令全文。以下仅示例：

```markdown
# 订单搜索
- 目标：增加按订单号搜索，保留分页和已有筛选。
- 设计：复用列表查询，在现有接口增加可选字段；旧调用方行为不变。
- 验收：匹配、无结果及与其他筛选组合均符合预期。
- 验证：填写实际命令或步骤、结果和必要环境；可引用原有 CI、测试输出。
- 未决事项：无，或具体问题及其影响。
```

进度用会话中的任务跟踪或此文件简短记录，选一个来源；默认不创建 tasks.md、单独检查报告或 evidence 目录。复查发现和需求差量也写在同一记录。记录够用即停止补文档，继续实现和验证。

## 针对性复查

普通 Spec 审查实际 diff、调用方兼容和关键失败路径即可。改变权限或敏感数据边界、外部副作用、不可逆、生产或批量行为时，增加未参与起草者的独立复查，聚焦改变的风险；同一 Agent 自审不能冒充独立复查。记录审核者、输入范围、结论及发现的处理，可直接附在同一 Spec，不强制另开报告。

本地实现及隔离测试可先进行；高风险部分交付或实际操作前须完成必要复查。缺少审核资源时说明缺口，继续不依赖未决结论的工作；未完成复查的高风险部分保留待处理。需求变更只复查受影响范围，复用结论时说明依据。

开发保存接口与执行真实写入分别判断。实际共享/外部写入、生产或不可逆操作前记录目标范围、预览或 dry-run、有效授权来源及重试/恢复边界，可复用现有工单或记录。用户已有授权涵盖当前操作时直接沿用；缺失或失效时补充。未经授权不 merge、push、部署或写生产数据。

## 验证与完成

按主流程执行项目要求和与改动相关的检查。保存足以复核的结果，优先引用已有日志、CI 或工具输出，不为每项验收复制证据。行为变化使旧证据失效时重验；其余结果可说明依据后复用。

验收满足、必要检查与复查通过且无阻塞时交付；缺环境或工具导致未验证的部分要明确说明。完成说明只写行为变化、验证结果和遗留项。

## 何时启用完整追踪

只有用户或项目明确要求结构化验收追踪，或长期、多阶段协作确需自动检查任务与验收映射时，才读取 [完整追踪记录](formal-records.md)，启用 templates/ 和 check_spec 脚本。单纯进入 Spec 或涉及高风险不自动要求多份文件。

已有完整记录的任务继续维护当前记录，不擅自删除或把未完成事项改成通过。后续独立任务按实际需要选择；无需将简短 Spec 转成机器格式。简短 Spec 不运行 check_spec，格式检查失败不应成为为普通开发补建文档的理由。
